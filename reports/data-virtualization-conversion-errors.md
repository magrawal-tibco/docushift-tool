# TIBCO Data Virtualization — conversion errors for review

**Product:** TIBCO® Data Virtualization (moved to the Spotfire business unit, Oct 2026)
**Versions:** 8.9.0, 8.8.1, 8.8.0, the three versions still in support
**Converted:** 2026-10-21/22, from the "Download All Docs" packages on docs.tibco.com
**Attachment:** `data-virtualization-broken-references.csv`, every broken reference with the page it is on and the page it most likely meant

## Summary

All three versions converted: 10,473–11,041 pages each, with nothing lost in conversion.
The conversion reported **one kind of error: 102 references per version that point at
nothing**. Every one of them is **broken in the source documentation itself**, not
something the conversion broke. They are the same 102 in all three versions, so the
fixes are the same each time.

| Problem | Per version | Where | Fix needed from |
|---|---|---|---|
| A link where the page name and the section name were glued together | 90 | Google Ads, Dynamics GP and HubSpot adapter guides | Doc team: confirm the intended pages. The CSV suggests one for every link |
| A link whose target is just a number (`4`, `5`) | 2 | Dynamics GP adapter guide | Doc team: confirm the intended pages. The CSV suggests them |
| An image that is not in the package | 6 | Web-based (SOAP/REST) adapter guide | Doc team: supply the 6 images, or agree to drop them |
| A web address written without `https://` | 4 (3 in 8.9.0) | Installation guide (Docker pages) | None. It can be corrected to `https://edelivery.tibco.com` |
| A stylesheet that refers to a missing file (`Spotfire.css`) | 1 (8.9.0 only) | Shared styles of the main guide set | None. It affects appearance only and the new site uses its own styling |

Readers see these as links that go nowhere or images that do not show. Because the
problems are in the source, the same pages are very likely broken on the current
docs.tibco.com too.

## 1. Links with the page name and section glued together (90 per version)

The adapter reference pages were generated by a tool that built some links by
joining a page file name and a section name with nothing in between. The link
should point at a separate page that **does exist** in the package.

| Link as written | Link text | Page that exists |
|---|---|---|
| `70Campaign.htmlstatsreport` | CampaignStatsReport | `87CampaignStatsReport.html` |
| `213OAuthJWTCert.htmlType` | OAuthJWTCertType | `214OAuthJWTCertType.html` |
| `213OAuthJWTCert.htmlPassword` | OAuthJWTCertPassword | `215OAuthJWTCertPassword.html` |
| `39GLTransaction.htmlines` | GLTransactionLines | `120GLTransactionLines.html` |
| `151ProjectContract.htmbillingcycles` | ProjectContractBillingCycles | `152ProjectContractBillingCycles.html` |
| `23HubSpotDataModel.htmv3` | HubSpot V3 Data Model | `106HubSpotV3DataModel.html` |

Where they are:

| Adapter guide | Broken links | Main page |
|---|---|---|
| Google Ads | 87 | `Views` (73 of them), plus the OAuth / JWT connection pages |
| Dynamics GP | 2 | `Views` |
| HubSpot | 1 | `Data Model` |

**Ask:** confirm that the "Likely intended page" column in the CSV is right. Where
two pages are suggested, the package holds two near-identical copies of that page
under different numbers, so please say which one is current. Once confirmed, the
links can be repointed during migration and need not stay broken on the new site.

## 2. Links whose target is just a number (2 per version)

On the Dynamics GP `Views` page, **ApplicantApplication** links to `4` and
**ApplicantApplications** links to `5`. Pages with those names exist
(`83/84ApplicantApplication`, `84/85ApplicantApplications`).

**Ask:** confirm which page each should open. It is in the same CSV.

## 4. Web addresses without `https://` (4 per version; 3 in 8.9.0)

On the Docker installation pages (*Building TDV Docker Images*, *Launching TDV
Containers*, *Launching TDV Containers (Single Node) Using Docker Compose*), the link
to the download site is written as `edelivery.tibco.com`. Without `https://` a
browser treats it as a file next to the page, so the link fails. No decision is
needed; the fix is mechanical.

## Other findings (warnings, not errors)

None of these block publishing. They are listed so the team knows they exist.

- **Old addresses that will not redirect.** After the move, an old docs.tibco.com
  address should forward to its new page. Every converted English help page has a
  forward. The old addresses without one are:

  | | 8.9.0 | 8.8.1 | 8.8.0 |
  |---|---|---|---|
  | Japanese edition (on the live site, but not in the download packages; see below) | 0 | 3,709 | 3,208 |
  | PDF guides (published on the new site, but old PDF links do not forward) | 90 | 90 | 88 |
  | Readme, release notes, accessibility statement, notice | 3 | 4 | 4 |
  | Help-system shells (home, contents and title frames, old templates) | 30 | 30 | 25 |
  | Long-term-support release lists | 8 | 0 | 1 |
  | **Total** | **131** | **3,833** | **3,326** |

  **Ask:** should old PDF links forward to the PDFs' new location, and should the
  help-system home pages forward to each guide's new home page? Neither is in place
  yet for any product, so this is a decision for the whole migration.
- **The Japanese edition of 8.8.0 and 8.8.1 cannot be migrated yet.** Translated
  documentation is now part of the migration, and it is published to a separate
  translated repository. But the download packages for 8.8.0 and 8.8.1 contain only the
  English help: the 6,917 Japanese pages exist on docs.tibco.com only. 8.9.0 has no
  Japanese edition.
  **Ask:** can the docs team supply the Japanese 8.8.0 and 8.8.1 help as packages? When
  they arrive, they are converted like the English and published to a new repository,
  `loc-spotfire-data-virtualization-userdocs`. That repository must be created first.
- **Links to a section that does not exist:** 83 (8.9.0), 88 (8.8.1), 62 (8.8.0).
  The page opens, but not at the intended section.
- **Pages not in any table of contents:** about 750–850 per version. They are
  converted and kept, but readers can only reach them from links.
- **Help-button maps are empty:** the five "context-sensitive help" maps in each
  package contain no entries, so no in-product Help button links carry over.
  **Ask:** confirm whether Data Virtualization's product UI opens help by topic ID.
- **8.9.0: 442 pages without the usual page layout** (the Deployment Manager guide)
  were converted from the whole page instead. Spot-checking a few is advisable.
- **8.9.0: 12 files in an `LTS` folder** (the long-term-support release lists) have
  no place in the help and were not converted.
- **4–5 auto-generated section overview pages per version** shared a name with a real
  page. The real page was kept, so no content is lost.
